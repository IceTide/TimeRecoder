# TimeRecoder — 技术选型与功能规划

> 目标：做一个对标 Rize 的**本地优先桌面时间管理应用**。Rize 本身是 Electron 桌面端，核心价值在于「不打断心流的时间记录 + 专注洞察」。本项目的 MVP 聚焦四大模块：**专注模式、日程安排、TODO、时间统计**。

---

## 一、产品定位

| 维度 | 说明 |
|---|---|
| 形态 | 桌面应用（Windows / macOS），离线可用 |
| 数据 | 本地存储为默认，隐私可控；后续可接入云同步 |
| 核心差异 | 不是又一个待办清单，而是「把时间、任务、日程、专注串成一条线」：TODO 决定做什么 → 日程决定何时做 → 专注模式执行并记录 → 时间统计复盘 |
| 第一版范围 | 手动/半自动记录（专注计时 + 手动补录），自动窗口追踪放 Phase 2 |

---

## 二、技术选型

### 2.1 决策总表

| 层次 | 选型 | 理由 | 备选与取舍 |
|---|---|---|---|
| 桌面壳 | **Electron** | Rize 同款路线；系统级 API（窗口监控、托盘、全局快捷键、通知）成熟，Phase 2 做自动追踪必需；跨平台一致 | Tauri 更轻但需 Rust 工具链、Windows 配置繁琐；当前阶段体积不是瓶颈，选 Electron |
| UI 框架 | **React 19 + TypeScript** | 生态最广、类型安全、组件化利于四大模块解耦 | Vue 亦可，但团队/资料生态 React 更稳 |
| 构建 | **Vite** | 冷启动快、HMR 顺滑、Electron 集成简单 | Webpack 配置繁重，不取 |
| 样式 | **原生 CSS + CSS 变量** | 零额外构建依赖、可控性强、支持明暗主题；减少工具链不确定性 | Tailwind 开发快但增配置面，MVP 阶段不用 |
| 状态管理 | **Zustand** | 轻量、无 Provider 样板、持久化中间件现成 | Redux 过重，Context 在高频计时下性能差 |
| 本地数据库 | **Dexie（IndexedDB）** | 事务、索引、查询能力完善，配 `dexie-react-hooks` 响应式；容量远大于 localStorage | better-sqlite3 需原生编译（Windows 易踩坑）；localStorage 容量/查询不足 |
| 图表 | **Recharts** | 声明式 React 图表，柱状/饼/折线/面积图覆盖统计需求 | — |
| 图标 | **lucide-react** | 轻量、风格统一 | — |
| 日期处理 | **date-fns** | 函数式、按需引入、Tree-shaking 友好 | moment 已过时 |
| 打包 | **electron-builder**（Phase 1 末接入） | 一键出安装包 | — |

### 2.2 关键设计决策

1. **计时不用「定时器累加」，用「时间戳差值」。**
   专注计时以 `startedAt` 时间戳为基准，`Date.now() - startedAt` 计算时长。这样即使 Electron 窗口休眠、setInterval 被节流，恢复后时间仍准确。

2. **数据层与 UI 解耦。**
   所有读写走 `src/db` 的 repository 层，UI 通过 Zustand store 调用。后续把 Dexie 替换成云 SDK / REST，只改数据层。

3. **Electron 主进程只做「系统能力」。**
   窗口管理、托盘、通知、全局快捷键、后续的活动窗口监控放主进程；业务逻辑全在渲染进程。两者通过 IPC + preload 安全通信。

4. **时间统一存 UTC 毫秒时间戳。**
   展示层再按本地时区格式化，避免跨时区/夏令时问题。

## 三、功能规划（MVP）

### 3.1 专注模式 Focus（P0）

- 选择要专注的任务（可关联 TODO / 项目），或从「自由专注」开始
- 预设时长：25 / 50 / 90 分钟，可自定义
- 计时状态：运行中 / 暂停 / 结束；显示进度环、剩余时间、当前任务
- 中断记录：暂停次数、切换次数（后续由窗口监控自动采集）
- 完成/放弃均落库为 `focusSession`，完成则同时生成一条 `timeEntry`
- 结束弹窗：本次专注时长、累计今日专注、休息提醒
- Phase 2：桌面勿扰、网站屏蔽、白噪音/专注音乐、全局快捷键

### 3.2 日程安排 Schedule（P0）

- 日 / 周视图切换，时间轴展示
- 新建 / 编辑 / 删除日程块（标题、起止时间、类型、颜色、关联任务）
- 「当前进行中」高亮，与专注模式联动（可从日程直接开启专注）
- 空闲时段提示（今日待办预计时长 vs 空闲时长）
- Phase 2：拖拽调整时间、日历导入（Google / Outlook）

### 3.3 TODO（P0）

- 任务字段：标题、项目、优先级、状态、预计时长、截止日期、标签、备注
- 视图：列表 + 按项目/状态/优先级筛选 + 关键词搜索
- 快速操作：新增、勾选完成、编辑、删除、开始专注
- 与日程/时间统计打通：任务可查看已投入时长
- Phase 2：子任务、重复任务、自然语言输入

### 3.4 时间统计 Statistics（P0）

- 时间范围：今日 / 本周 / 本月
- 总览卡片：总记录时长、专注时长、任务完成数、日均专注
- 图表：
  - 按项目分布（饼图）
  - 每日时长趋势（柱状图）
  - 专注 vs 会议 vs 杂项构成（堆叠/饼图）
  - 时段热力图（Phase 2）
- 明细列表：按时间倒序的时间条目，可编辑/删除/补录
- Phase 2：AI 自动归类、客户报告导出、效率洞察

### 3.5 全局（P0）

- 左侧导航 + 顶部状态栏（当前日期、正在进行的专注）
- 项目/标签管理
- 设置：专注时长预设、休息提醒、主题、工作时间段
- 数据导入导出（JSON 备份）

## 四、数据模型

```ts
Project      { id, name, color, createdAt }
Task         { id, title, projectId?, priority, status, estimatedMin?,
               dueDate?, tags[], note?, createdAt, completedAt? }
TimeEntry    { id, taskId?, projectId?, category, startAt, endAt,
               durationSec, source: 'focus'|'manual'|'auto', note? }
FocusSession { id, taskId?, plannedMin, startAt, endAt?, pauseCount,
               status: 'running'|'completed'|'aborted' }
CalendarEvent{ id, title, startAt, endAt, type, color?, taskId?, note? }
Settings     { key, value }   // 单键存储
```

`TimeEntry` 是统计的唯一事实来源；专注完成、手动补录、后续自动追踪都写入这张表。

## 五、UI 布局

```
┌────────────┬──────────────────────────────────────────┐
│            │  顶部栏：日期 / 全局专注状态 / 设置       │
│  侧边栏     ├──────────────────────────────────────────┤
│  · 专注     │                                          │
│  · 日程     │                                          │
│  · TODO    │            主内容区                       │
│  · 统计     │                                          │
│  ────────   │                                          │
│  项目列表   │                                          │
│  + 新建项目 │                                          │
└────────────┴──────────────────────────────────────────┘
```

视觉基调：浅色为主、克制的中性灰 + 单一强调色（专注态切换到深色沉浸模式），圆角卡片、留白充足，接近 Rize 的清爽感。

## 六、开发路线图

- **Phase 1（当前 MVP）**：Electron 壳 + 四大模块 + Dexie 本地存储 + 基础图表 + 构建可跑
- **Phase 2**：自动活动窗口追踪与 AI 归类、系统托盘 / 全局快捷键 / 通知、网站与应用屏蔽、日历双向同步
- **Phase 3**：报告导出、云同步与多端、团队协作与客户 profitability、效率洞察

---

## 七、与 Rize 的差异与取舍（坦诚说明）

| Rize 能力 | 本 MVP | 说明 |
|---|---|---|
| 自动后台追踪应用/网站时间 | ❌ → Phase 2 | 需要窗口标题采集 + 分类引擎，属核心但工程量大，先以手动/专注计时覆盖主路径 |
| AI 自动归类 | ❌ → Phase 2/3 | 需要模型调用，可在云同步阶段接入 |
| 专注检测 / 防干扰 | 🟡 基础 | 先做番茄钟与中断计数，屏蔽放 Phase 2 |
| 账单 / 客户 profitability | ❌ → Phase 3 | 偏团队/商业化，个人版 MVP 不取 |
| 日程 / TODO / 时间统计 | ✅ | 本 MVP 完整实现 |
